# DNAfetch v3 — Документация для автора

Ты создал переводчик. Входной язык — ДНК (4 буквы). Выходной язык — ProcessLang (10 команд). Этот документ объясняет что делает каждая часть системы и как читать результат.

---

## Что делает DNAfetch

ДНК — это текст из 4 букв: A, T, G, C. Этот текст читается тройками (кодонами). Каждая тройка кодирует одну аминокислоту. Цепочка аминокислот складывается в белок. Белок делает работу в организме.

DNAfetch берёт этот текст, заменяет каждую букву на оператор ProcessLang, и считает статистику: какие операторы доминируют, как они сочетаются, насколько система сбалансирована. Результат записывается в `.dpl` файл — 10 секций, по одной на каждую команду ProcessLang.

---

## Маппинг: почему именно так

```
A (аденин)  → FLOW
T (тимин)   → OBSERVE
G (гуанин)  → LOGIC
C (цитозин) → CHOOSE
```

Это не произвольный выбор. За каждым маппингом стоит химическая логика.

**A → FLOW.** Аденин — основа АТФ (аденозинтрифосфат), главной энергетической валюты клетки. Всё что движется в клетке, движется на АТФ. Аденин = энергия = поток.

**T → OBSERVE.** Тимин всегда парен аденину (A=T). Он не делает ничего сам — он «наблюдает» за потоком через комплементарную связь. Два водородных мостика — слабая связь, лёгкое наблюдение.

**G → LOGIC.** Гуанин образует тройную водородную связь (G≡C). Три связи — жёсткая, структурная фиксация. Это правило, каркас, логика. GC-богатые участки ДНК термически стабильнее — они буквально жёстче.

**C → CHOOSE.** Цитозин парен гуанину. Но в отличие от тимина, цитозин — самый мутабельный нуклеотид. Он легко деаминируется (теряет аминогруппу) и превращается в урацил. Это точка, где система «выбирает» — мутировать или нет. Выбор = коллапс возможностей.

## Три позиции в кодоне

Кодон — тройка нуклеотидов. Но три позиции не равны.

**Позиция 1 (primary).** Определяет класс аминокислоты. Если первая буква — это A (FLOW), аминокислоты будут одного типа. Если G (LOGIC) — другого. Это самый грубый фильтр.

**Позиция 2 (modifier).** Уточняет конкретную аминокислоту внутри класса. Вместе с первой позицией практически однозначно определяет свойства белка.

**Позиция 3 (wobble).** Самая интересная. Третья позиция часто может быть любой — белок не изменится. GCT, GCC, GCA, GCG — все кодируют аланин. Это «свобода выбора» внутри ограничений. Именно wobble-позиция показывает не ЧТО кодирует ген, а КАК он это кодирует. Стратегию, а не функцию.

**Аналогия из ProcessLang.** Позиции 1+2 — это ENCODE (что кодируется). Позиция 3 — это CHOOSE (как выбрана конкретная форма из множества эквивалентных).

## Как читать .dpl файл

### [IDENTITY]

Метаданные. Название гена, организм, длина белка. Не ProcessLang, просто заголовок.

### [FLOW]

Общая картина. Какой оператор доминирует во всём гене.

```
dominant = CHOOSE        # Этот ген — про выбор
dominant_pct = 0.2664    # CHOOSE = 26.64% всех нуклеотидов
FLOW = 0.2564           # Близко к CHOOSE — почти баланс
```

Параметры `engagement` и `resistance` — производные от энтропии распределения. Высокий engagement (близко к 1.0) означает что распределение очень ровное, все операторы почти поровну. Это «текучее» состояние — нет сильного перекоса.

**Что это значит.** Если доминирует FLOW — ген про движение, перенос. LOGIC — про структуру, каркас. CHOOSE — про связывание, селекцию. OBSERVE — про рецепцию, наблюдение за средой.

### [CONNECT]

Что делает белок в пространстве. Как он взаимодействует с окружением.

```
type = membrane_embedded    # Белок сидит в мембране
hydrophobic_ratio = 0.55    # Больше половины аминокислот гидрофобные
```

`depth` — это complementary balance (баланс A=T и G≡C). В природе A≈T и G≈C (правило Чаргаффа). Чем ближе к 1.0, тем «глубже» связь, тем естественнее ген.

Типы:
- `membrane_embedded` — белок внутри мембраны (каналы, рецепторы)
- `ionic_interaction` — много заряженных аминокислот (ферменты)
- `soluble_mediator` — растворимый посредник (гормоны, цитокины)
- `balanced_interface` — сбалансированный профиль

### [DISSOLVE]

Потенциал мутаций. Насколько этот ген «текуч» или «кристаллизован».

```
potential = crystallized    # Мутации маловероятны
rigidity = 0.9461          # Очень жёсткая структура
wobble_entropy = 0.0539    # Wobble-позиция предсказуема
```

Высокая rigidity + low wobble_entropy = ген сильно оптимизирован, каждый нуклеотид «на своём месте». Мутации в таком гене с большей вероятностью будут вредными.

Низкая rigidity + high wobble_entropy = ген «расслаблен», wobble-позиция варьируется свободно. Мутации в wobble чаще нейтральны.

### [ENCODE]

Стратегия кодирования. Как организм «оптимизировал» этот ген.

```
type = optimized           # Средне-высокая оптимизация
gc_content = 0.5226        # 52% G+C — чуть выше среднего
wobble_gc = 0.6792         # В wobble-позиции 68% G или C
codon_diversity = 0.9688   # Используются почти все возможные кодоны
```

Шкала `type`:
- `AT_rich` (wobble GC < 30%) — A и T доминируют в wobble
- `natural` (30-45%) — естественное распределение, минимальная оптимизация
- `moderate` (45-60%) — средняя оптимизация
- `optimized` (60-75%) — высокая оптимизация для экспрессии
- `engineered` (>75%) — экстремальная оптимизация (вакцины, синтетика)

**Ключевой инсайт.** Ebola = `natural` (39% wobble GC). COVID-19 = сильный A-bias в wobble. Pfizer вакцина = `engineered` (81% wobble GC). Один и тот же белок (Spike), три совершенно разных `[ENCODE]` профиля. ENCODE ловит КТО и КАК кодировал, не ЧТО.

### [CHOOSE]

Профиль wobble-позиции. Самая информативная секция.

```
dominant = CHOOSE           # В wobble чаще всего C
dominant_pct = 0.3747       # 37.5% всех wobble = C
wobble_FLOW = 0.1311        # A в wobble — редко (13%)
wobble_OBSERVE = 0.1898     # T в wobble — нечасто
wobble_LOGIC = 0.3044       # G в wobble — часто
wobble_CHOOSE = 0.3747      # C в wobble — чаще всего
```

Wobble — это «свободный выбор» организма. Из 4 возможных нуклеотидов в третьей позиции организм выбрал именно этот. Профиль wobble — это отпечаток пальца стратегии оптимизации.

### [OBSERVE]

Симметрия между операторами.

```
distance = 0.0100          # Разница между top-1 и top-2 оператором
level = strong              # Высокая симметрия
```

`distance` — это разница в частоте между первым и вторым по частоте оператором (top2 gap). Чем меньше — тем симметричнее система.

Шкала:
- `intense` (<0.5%) — два оператора почти идентичны по частоте
- `strong` (0.5-2%) — очень близки
- `deep` (2-5%) — заметная близость
- `standard` (5-8%) — нормальное распределение
- `mild` (8-12%) — один оператор заметно доминирует
- `basic` (>12%) — сильный перекос

**Что это значит в ProcessLang.** Маленький distance = система «наблюдает себя» через два почти равных оператора. Это внутренний баланс, саморефлексия. Большой distance = система однозначно «решила» в пользу одного оператора — никакой рефлексии, чистое исполнение.

### [CYCLE]

Паттерны переходов между операторами внутри кодонов (COMPOSE).

```
stability = strong
top_compose = FLOW→FLOW     # Самый частый переход
top_compose_pct = 0.1170    # 11.7% всех кодонов
compose_top5 = [
  FLOW→FLOW: 0.1170
  CHOOSE→OBSERVE: 0.0996
  LOGIC→FLOW: 0.0928
  ...
]
```

COMPOSE — это переход primary→modifier (позиция 1 → позиция 2). Он показывает какой «процесс» происходит внутри каждого кодона.

Типичные сигнатуры:
- **FLOW→FLOW** — поток→поток. Ионные каналы, транспортные белки. Непрерывное движение.
- **LOGIC→LOGIC** — правило→правило. Структурные белки (коллаген). Жёсткая повторяющаяся структура.
- **CHOOSE→CHOOSE** — выбор→выбор. Рекурсивная селекция. Рецепторы, антитела — белки которые «выбирают» что связывать.
- **CHOOSE→OBSERVE** — выбор→наблюдение. Сигнальные пептиды. Выбрал цель — наблюдай за ответом.
- **LOGIC→FLOW** — правило→поток. Ферменты. Правило (катализ) запускает поток (реакцию).
- **FLOW→OBSERVE** — поток→наблюдение. Рецепторы сигналов. Получил поток — наблюдай.

`stability` показывает насколько один COMPOSE-паттерн доминирует:
- `dominant` (>12%) — один паттерн явно главный
- `strong` (9-12%) — сильное предпочтение
- `moderate` (7-9%) — умеренное
- `distributed` (<7%) — все паттерны примерно равны

### [LOGIC]

Распределение операторов по позициям 1 и 2 отдельно.

```
primary_dominant = FLOW     # В позиции 1 чаще всего A
primary_pct = 0.2850        # 28.5%
modifier_dominant = OBSERVE # В позиции 2 чаще всего T
modifier_pct = 0.2980       # 29.8%
```

Это «правила» по которым ген строит свои кодоны. Primary определяет класс, modifier уточняет. Вместе они определяют аминокислоту.

### [RUNTIME]

Аминокислотный состав — «подсознательная основа» белка.

```
aa_std = 0.0203            # Стандартное отклонение частот аминокислот
aa_top5 = [
  Leu: 0.0935  # nonpolar     — лейцин, гидрофобный
  Ser: 0.0846  # polar        — серин, полярный
  Glu: 0.0778  # negative     — глутамат, отрицательный заряд
  ...
]
```

`aa_std` показывает насколько равномерно распределены аминокислоты. Низкий std = белок использует все аминокислоты примерно поровну. Высокий std = перекос в сторону определённых аминокислот (специализация).

### [MANIFEST]

Класс белка — финальная «материализация».

```
format = regulatory         # Белок-регулятор
protein_length = 1464       # Длина в аминокислотах
stop_codon = TAA            # Стоп-кодон
```

Классы:
- `structural` — каркас (коллаген, кератин). Много глицина и пролина.
- `signaling_peptide` — короткий сигнал (инсулин, окситоцин). Много цистеина, маленький размер.
- `transmembrane` — мембранный (каналы, рецепторы). Много лейцина.
- `regulatory` — регулятор (транскрипционные факторы). Много серина.
- `enzymatic` — фермент (катализ реакций). Всё остальное.

### [SIGNATURE]

Однострочный fingerprint, комбинация ключевых классификаций.

```
fingerprint = CHOOSE.CHOOSE.strong.strong.crystallized.balanced_interface
```

Формат: `dominant.wobble_dominant.observation.cycle.dissolution.connection`

Этим можно быстро сравнивать гены не открывая полный `.dpl`.

## Конвейер обработки

```
FASTA файл
    │
    ▼
fetch.py ─── парсит файл, находит CDS, разбивает на кодоны
    │         определяет аминокислоты, свойства белка
    ▼
translate.py ─ заменяет A→FLOW, T→OBSERVE, G→LOGIC, C→CHOOSE
    │           считает частоты по 3 позициям
    │           считает COMPOSE-пары (primary→modifier)
    │           считает GC-контент, entropy, баланс
    ▼
describe.py ── формирует .dpl файл
    │           классифицирует по порогам
    │           генерирует SIGNATURE
    ▼
GENE.dpl файл
```

---

## Что означают числовые пороги

Пороги калиброваны по трём контрольным точкам:

1. **Ebola** — природный вирус с миллионами лет эволюции. Wobble GC = 39%. Комплементарный баланс идеальный (A≈T, G≈C). Это «ноль» шкалы — чистая природа.

2. **Pfizer BNT162b2** — синтетический конструкт, спроектированный людьми. Wobble GC = 81%. Экстремальная оптимизация. Это «сто» шкалы — чистая инженерия.

3. **COVID-19** — wobble A-bias 44%, GC ~42%. Не похож ни на Ebola (природу), ни на Pfizer (инженерию). Аномальная точка для калибровки.

Когда DNAfetch говорит `type = optimized` или `type = engineered`, он сравнивает с этими тремя точками.

## Ограничения

**DNAfetch не предсказывает функцию.** Он описывает стратегию кодирования. LOGIC→LOGIC для коллагена — это не предсказание, это описание факта что в коллагене много GGN-кодонов (глицин). Маппинг совпадает с биологией, но это корреляция, не каузация.

**Классификация `[MANIFEST]` грубая.** Пять классов на 20 000 белков — это очень грубо. Она основана на простых порогах аминокислотного состава. Для машины это стартовая точка, не финальный вердикт.

**Wobble-анализ работает только для кодирующих последовательностей (CDS).** Если подать UTR, интроны или межгенные участки — wobble-позиция теряет смысл, потому что нет рамки считывания.

**Маппинг 4→4 неизбежно теряет информацию.** A→FLOW — это метафора. Аденин делает много вещей помимо «потока». Маппинг схватывает доминантное свойство, не полную картину.
