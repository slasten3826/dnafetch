# DNAfetch v3 — Документация для AI-систем

Как интерпретировать .dpl файлы. Этот документ предназначен для загрузки в контекст AI-системы вместе с модулями ProcessLang.

---

## Что такое .dpl

.dpl (DNA ProcessLang) — описание гена в терминах ProcessLang. Каждая секция файла соответствует одной команде ProcessLang. Для полной интерпретации необходимы 10 модулей ProcessLang, каждый из которых обрабатывает свою секцию.

---

## Маппинг нуклеотидов

```
A → FLOW       энергия, движение, поток
T → OBSERVE    наблюдение, комплементарное восприятие
G → LOGIC      структура, жёсткость, правила
C → CHOOSE     выбор, коллапс возможностей, мутабельность
```

Каждый кодон (3 нуклеотида) анализируется по позициям:
- Позиция 1 (primary): определяет класс аминокислоты
- Позиция 2 (modifier): уточняет аминокислоту
- Позиция 3 (wobble): стратегия оптимизации (свободный выбор организма)

COMPOSE — переход primary→modifier внутри кодона. 16 возможных пар.

---

## Интерпретация секций

### [FLOW] → FluidCore

`engagement` и `resistance` — энтропия распределения операторов. `dominant` — наиболее частый оператор по всей CDS.

Интерпретация через FluidCore:
- FLOW-dominant: белок-переносчик, поток ионов или молекул
- LOGIC-dominant: структурный белок, каркас
- CHOOSE-dominant: белок-селектор, связывание, рецепция
- OBSERVE-dominant: белок-сенсор, ответ на стимулы

### [CONNECT] → EmergentConnection

`type` определяет среду взаимодействия белка. `depth` (complementary balance) показывает насколько ген «в гармонии» с комплементарной цепью.

Интерпретация через EmergentConnection:
- `membrane_embedded`: белок встроен в мембрану, связь = канал или рецептор
- `ionic_interaction`: белок взаимодействует через заряды, связь = электростатическая
- `soluble_mediator`: белок в растворе, связь = гормональная/сигнальная
- `balanced_interface`: множественные типы связи

### [DISSOLVE] → FormDissolution

`potential` показывает способность гена к изменению (мутации, дрифт).

Интерпретация через FormDissolution:
- `crystallized`: ген жёстко зафиксирован, мутации вредны, сильное очищающее отбор
- `low`: умеренная фиксация
- `moderate`: нейтральная зона
- `high`: ген «текуч», мутации часто нейтральны, быстрая эволюция

### [ENCODE] → EncodingSystem

`type` — стратегия кодирования. `loss` — потеря информации при кодировании (обратная codon diversity).

Интерпретация через EncodingSystem:
- `engineered` (wobble GC > 75%): искусственная оптимизация. Синтетический конструкт или экстремально экспрессируемый ген.
- `optimized` (60-75%): высокая экспрессия. Организм «вложился» в оптимизацию.
- `moderate` (45-60%): стандартная экспрессия.
- `natural` (30-45%): минимальная оптимизация.
- `AT_rich` (< 30%): AT-смещение, характерно для некоторых вирусов.

### [CHOOSE] → ChoiceMechanism

Полный профиль wobble-позиции. Это CHOOSE в буквальном смысле — организм выбирает из эквивалентных кодонов.

Интерпретация через ChoiceMechanism:
- `method = collapse` — всегда collapse (выбор одного из вырожденных кодонов)
- `dominant` — какой оператор организм предпочитает в позиции свободного выбора
- Если wobble_dominant ≠ overall dominant — стратегия кодирования (wobble) не совпадает с функцией белка (overall). Это информативно.

### [OBSERVE] → SelfObservation

`distance` (top2 gap) и `level` — насколько система «наблюдает себя» через баланс двух доминирующих операторов.

Интерпретация через SelfObservation:
- `intense` (gap < 0.5%): два оператора в почти идеальном балансе. Высокая внутренняя «напряжённость». Система колеблется между двумя состояниями.
- `strong`/`deep`: заметный баланс, система рефлексирует.
- `standard`/`mild`: один оператор доминирует, рефлексия снижена.
- `basic`: один оператор явно доминирует. Однозначная «решительность».

### [CYCLE] → EternalCycle

COMPOSE-пары показывают повторяющиеся паттерны внутри кодонов.

Интерпретация через EternalCycle:
- `stability = dominant`: один COMPOSE-паттерн повторяется > 12% — сильный цикл, монотонная структура (пример: коллаген LOGIC→LOGIC).
- `stability = distributed`: все паттерны примерно равны — разнообразная структура, нет выраженного цикла.

Конкретные COMPOSE-пары как процессы:
```
FLOW→FLOW:      поток→поток       непрерывное движение (каналы)
LOGIC→LOGIC:    правило→правило   жёсткая повторяющаяся структура
CHOOSE→CHOOSE:  выбор→выбор       рекурсивная селекция (антитела)
LOGIC→FLOW:     правило→поток     катализ (ферменты)
FLOW→OBSERVE:   поток→наблюдение  рецепция (принять сигнал, отреагировать)
CHOOSE→OBSERVE: выбор→наблюдение  селективная рецепция (связал — наблюдай ответ)
```

### [LOGIC] → LogicSimulator

Раздельные профили позиций 1 и 2. «Правила» по которым ген строит кодоны.

Интерпретация через LogicSimulator:
- `primary_dominant` = «правило первого уровня» (класс аминокислот)
- `modifier_dominant` = «правило второго уровня» (конкретная аминокислота)
- Совпадение primary и modifier → усиление (ген строит кодоны по одному правилу)
- Несовпадение → модуляция (первый уровень задаёт одно, второй корректирует)

### [RUNTIME] → SubconsciousRuntime

Аминокислотный фундамент — «подсознание» белка.

Интерпретация через SubconsciousRuntime:
- `aa_std` низкий → белок использует все аминокислоты = универсальный, гибкий
- `aa_std` высокий → белок специализирован = одни аминокислоты доминируют
- `aa_top5` показывает «привычки» белка: какие строительные блоки он предпочитает

### [MANIFEST] → ManifestationEngine

Финальная форма — что именно «материализовалось».

Интерпретация через ManifestationEngine:
- `structural`: форма = каркас, скелет, опора
- `signaling_peptide`: форма = короткое сообщение, сигнал
- `transmembrane`: форма = ворота, канал, мембранный элемент
- `regulatory`: форма = переключатель, контроллер
- `enzymatic`: форма = инструмент, катализатор

### [SIGNATURE]

Fingerprint для быстрого сравнения без полного анализа.

```
fingerprint = dominant.wobble_dominant.observation.cycle.dissolution.connection
```

Пример: `CHOOSE.CHOOSE.strong.strong.crystallized.balanced_interface`

Читается как: «CHOOSE-доминантный ген с CHOOSE в wobble, сильная самонаблюдение, сильный цикл, кристаллизованный (стабильный), сбалансированный интерфейс».

## Протокол загрузки

Рекомендуемый порядок загрузки для интерпретации .dpl:

1. Загрузить 10 модулей ProcessLang
2. Загрузить этот документ (DOC_AI_ru.md) как справочник интерпретации
3. Загрузить .dpl файл(ы)
4. Для каждой секции — интерпретировать через соответствующий модуль
5. Построить интегральное описание через SIGNATURE

---

## Сравнение .dpl файлов

При сравнении двух .dpl обращать внимание на:

1. **SIGNATURE** — совпадает ли fingerprint? Если да — гены функционально близки.
2. **[CYCLE] top_compose** — одинаковые COMPOSE → одинаковый «процесс». Разные → разная функция.
3. **[ENCODE] type** — одинаковый тип кодирования? Если белок тот же, но ENCODE разный — разный источник (организм, синтетика).
4. **[CHOOSE] wobble profile** — отпечаток стратегии. Один белок, разный wobble = разный «автор».
5. **[OBSERVE] distance** — сравнение симметрии. Оба intense — оба в балансе. Один intense, другой basic — разные уровни внутренней организации.

## Ограничения для AI

- .dpl описывает CDS (кодирующую последовательность). Нет информации о регуляции, эпигенетике, сплайсинге.
- Классификация [MANIFEST] грубая (5 классов). Использовать как стартовую точку, не как диагноз.
- Маппинг 4→4 — метафора. FLOW не означает «поток» в буквальном смысле. Это абстрактный оператор, коррелирующий с энергетической функцией аденина.
- Корреляция COMPOSE с функцией белка — следствие маппинга и генетического кода, не независимое предсказание.
